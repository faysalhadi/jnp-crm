# REMOVE THE CHAT WINDOW — client view becomes Notes & Activity only

The in-app message thread duplicates WhatsApp and is never used. Only notes,
activity logging and follow-ups are used. Remove the chat metaphor and make
NotesActivityView the single body of the client detail view.

Read every file before editing. This is a deletion task — be careful not to
remove things that other parts of the app still depend on.
After all changes: npm run build, fix ESLint errors, git push.

---

## STEP 0 — Find out what actually depends on the chat pieces

Before deleting anything, run these and read the output:

```bash
grep -rn "MessageList" src/
grep -rn "InputBar" src/
grep -rn "messageService" src/
grep -rn "useChatActions" src/
grep -rn "ChatContext\|useChat" src/
grep -rn "from('messages')" src/
```

Keep a note of every hit. Some of these files hold non-message logic
(selected customer state, tag updates, deal actions) that MUST survive.
Do not delete a file that still has a live import after this refactor.

---

## STEP 1 — src/components/chat/ChatDetailView.js

Read the file.

This stays as the client detail screen — do not delete it. Change its body:

### 1a. Remove the message thread
- Remove the `<MessageList />` render and its import.
- Remove the `<InputBar />` render and its import.
- Remove any message-fetching state and effects (messages array, loading
  messages, subscriptions to a messages table, scroll-to-bottom refs).

### 1b. Make NotesActivityView the body

`NotesActivityView` should now fill the space the message thread occupied —
full height, scrollable, directly under `ChatHeader`.

```jsx
<div style={{ display: 'flex', flexDirection: 'column', height: '100%' }}>
  <ChatHeader customer={customer} ... />
  <div style={{ flex: 1, overflowY: 'auto' }}>
    <NotesActivityView customer={customer} ... />
  </div>
</div>
```

### 1c. If there is a tab switcher (Chat / Notes / Preferences)

If ChatDetailView has tabs to switch between the message thread and notes,
remove the Chat tab entirely. If Notes was the only other tab, remove the
whole tab switcher — there is nothing left to switch between.

Keep any Preferences / Consignment / Supplier-notes panels that exist as
separate tabs, but Notes & Activity must be the default landing tab.

### 1d. Keep the not-found guard

```jsx
if (!customer) {
  return (
    <div style={{ padding: 32, textAlign: 'center', color: '#7880A3', fontSize: 13 }}>
      Client not found. Go back and try again.
    </div>
  );
}
```

## STEP 2 — src/components/chat/ChatHeader.js — add the WhatsApp button

Read the file.

The header must keep everything it has (name, tags section, order frequency,
quote prompt, loss reason, stage bar, assignment dropdown) and gain a clear
way to reach the real WhatsApp conversation, since that is now the only place
messages live.

Add a WhatsApp action button in the header actions row:

```jsx
import { openWhatsApp } from '../../utils/whatsapp';
// check the actual export name in src/utils/whatsapp.js first

<button
  onClick={() => openWhatsApp(customer.number, '', myWhatsApp)}
  style={{
    background: '#12301F',
    border: '1px solid #1E4A31',
    color: '#2EC97A',
    borderRadius: 8,
    padding: '6px 12px',
    fontSize: 12,
    fontWeight: 600,
    cursor: 'pointer',
    display: 'flex',
    alignItems: 'center',
    gap: 6,
  }}
>
  💬 WhatsApp
</button>
```

Hide it when the owner is in read-only view-as mode:

```jsx
{!isViewingAs && customer.number && ( ...the button... )}
```

Match the existing signature of the whatsapp helper — read
src/utils/whatsapp.js and use whatever it actually expects.

## STEP 3 — Delete the message-only files

Only delete a file if STEP 0 showed it has no remaining importers after
steps 1 and 2.

Almost certainly safe to delete:
```bash
git rm src/components/chat/MessageList.js
git rm src/components/chat/InputBar.js
```

Check before deleting:
- `src/services/messageService.js` — delete ONLY if nothing else imports it.
  If BroadcastService, useBroadcast, or the sourcing module import from it,
  keep the file and remove only the per-client message functions.
- `src/context/ChatContext.js` — this likely holds `selectedCustomer` and view
  state, NOT just messages. Do NOT delete it. Remove only the message-specific
  state and functions (messages array, sendMessage, fetchMessages, realtime
  subscription) and leave the rest intact.
- `src/hooks/useChatActions.js` — same. Remove message send/fetch actions,
  keep deal/stage/tag actions.

Also delete the long-dead file while you are in here:
```bash
git rm src/components/chat/FollowUpPanel.js
```
(the project notes mark it DEPRECATED — NotesActivityView replaced it
everywhere). Confirm with `grep -rn "FollowUpPanel" src/` returning nothing
before removing.

## STEP 5 — NotesActivityView polish

Read src/components/chat/NotesActivityView.js.

Now that this is the whole client screen rather than a secondary tab, make
sure it reads well at full height:

- The activity buttons row (Called, No Answer, Messaged, Met, Note) should be
  pinned near the top, easy to reach with a thumb — it is the primary action
  on this screen now.
- The follow-up section (set / edit / done / delete) comes next.
- The activity feed fills the rest and scrolls.
- If the feed is empty, show a short empty state rather than blank space:
  "No activity yet — log a call or add a note to start."

Do not change its data logic. This is layout only.

---

## STEP 6 — Database (do nothing yet)

Leave any `messages` table in Supabase alone. Removing the UI is reversible;
dropping the table is not. If it is still empty and unused in a month, drop it
then.

## STEP 7 — Build and push

```bash

```

Fix all ESLint errors. Expect a lot of "unused variable" warnings from the
removed imports — clear every one.

```bash

```

## TEST AFTER DEPLOY

1. Open any client — you land straight on Notes & Activity, no message thread
2. The activity buttons work and log to activity_log
3. Set a follow-up — it appears on the Home tab
4. Tap 💬 WhatsApp — opens the real WhatsApp thread with that client
5. As a salesperson, add a new client and open it — the detail view loads
   with the client name in the header and an empty activity state
6. As owner in "view as" mode, the client view is read-only: no activity
   buttons, no follow-up buttons, no WhatsApp button
