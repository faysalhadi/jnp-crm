── SCREEN 1: what do they want ─────────────────────────────────────────
 
  Brand      (required)
  Model      (required)
  Quantity   (required, integer, default 1)
 
  Brand and model are REQUIRED. Block save and explain why:
    "Without brand and model we can't match this when stock arrives."
 
  As soon as brand + model are filled, compute the pool live using
  modelKey() + buildStockPools() and show it under the fields:
 
      You have 130 free · 50 held · 20 sold
 
  If there is no pool for that model, show "None in stock".
 
  [ Next ]
 
── SCREEN 2: the fork — DERIVED, not asked blindly ─────────────────────
 
  Compare quantity wanted against pool.free and show ONLY the doors that
  make sense. Do not offer "allocate all" when there is nothing to allocate.
 
  Header:  "They want 60 · you have 130 free"
 
  free >= wanted        → show doors A and C
  0 < free < wanted     → show doors B and C
  free === 0            → show door C only, and skip straight to it
 
  DOOR A — "Allocate all 60"        (green)
    stage = 'device_found'
    Then reveal:
      Unit price   (AED, required)
      [ ] Hold 60 units for 48h      ← UNCHECKED BY DEFAULT
    Live total under the price field: 60 × 800 = AED 48,000
 
    The hold checkbox is MANUAL and off by default. Only pre-check nothing,
    ever. But when wanted > 50% of free, show an amber nudge above it:
      "You're quoting 60 of 130 free. Worth holding."
 
  DOOR B — "Allocate 30, source 30"  (amber)
    stage = 'sourcing'
    Fields: Unit price (optional), same manual hold checkbox for the
    portion you have.
    Note on the deal records the split.
    Reason it is 'sourcing' not 'device_found': the job isn't done until
    the remainder is found.
 
  DOOR C — "Not in stock — go looking"  (purple)
    stage = 'sourcing'
    sourcing_started_at = now()
    Field: "What would he pay per unit" (optional) → target_unit_price
    NO hold, NO unit price required.
 
  Every door writes: customer_id, brand, model, quantity, created_by,
  and creates an activity_log note describing what was recorded.
 
  Doors A and B create a 24h follow_up. Door C does NOT — sourcing is
  tracked by its own clock in the queue, not by a follow-up.
 
  A summary block before saving, listing exactly what will happen. Same
  pattern as the park sheet.
 
  A Back link returns to screen 1 and keeps everything typed.
 
IMPORTANT: parking is NOT a door here. Parking is a later decision made on
an existing deal when it stops progressing. Do not offer it at creation.
